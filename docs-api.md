The handbook feed uses Luminara's version 1 shape: `{ version: 1, menu, pages }`.
Each page includes its `/help/` path, frontmatter metadata, and Markdown without
frontmatter. The menu uses the same titles and hierarchy as the website.

Run `vp run build` after editing documentation. The API route handlers and the
help layout loader read Markdown directly through Vite's build-time imports.
Qwik prerenders the API responses and serializes the website metadata into the
static help pages for navigation and search. Documentation comes from
`src/routes/help/**/index.md` (or `.mdx`); no generated source manifest, separate
generation script, or runtime server is required.

GitHub Pages serves the build artifact `dist/api/docs/index.html` at `/api/docs/`,
so clients using Luminara's endpoint can parse the response as JSON. Pages sends
that directory index with an HTML content type. Clients requiring
`application/json` should use `/api/docs/index.json`, which contains identical
JSON. Both are generated by Qwik from the API route handlers; no feed copies are
maintained in `public/`. GitHub Pages controls caching and response headers.

Metadata supports `title`, `description`, `keywords`, `icon`, `extra_buttons`
(`label`, `href`, optional `icon`), `contributors`, `date_created`, and
`last_updated`. Existing `created_at` and `updated_at` dates also populate the
corresponding Luminara fields in the feed. Extra buttons targeting pages outside
the feed are omitted. The feed also understands Luminara's `audience` metadata
and audience section markers for Minecraft consumers.
